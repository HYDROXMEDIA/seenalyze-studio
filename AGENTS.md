# SEENALYZE STUDIO desktop — Agent Operating Guide

Inherits `~/Desktop/dev/AGENTS.md` (security, blind `.env` §10, no silent errors §10a, bold end-of-response summary) and all system/user rules; only adds project detail.

## Purpose and boundaries
Desktop live-streaming studio (Electron, macOS + Windows) with native multistreaming, plus screen recording with an editor (automatic zooms, redrawn pointer, camera, backgrounds, cuts, captions, export). One encode is shared by every destination with identical video settings; each destination has its own connection, reconnect loop, and statistics. Video goes straight from the user's machine to each platform, never through a relay.
- **Public, GPL-2.0-or-later repository** (links libobs). Never add proprietary code, secrets, server credentials, or private dashboard source.
- The private service (accounts, billing, OAuth brokering where a platform needs a client secret) is `../backend`, a separate repository. Never import between them.
- Platforms: **YouTube and Twitch only** unless the maintainer asks.

## Layout
- `src/main/`: Electron main (window, IPC, persisted state, secrets, platform APIs in `platforms/`); `studio.ts` implements the IPC API and never calls libobs directly.
- `src/main/engine/`: libobs in a **separate utility process** (`worker.ts`, driven by `client.ts`). `osn.ts` loader, `engine.ts` canvas/encoders/teardown, `scenes.ts`, `audio.ts`, `preview.ts`, `outputs.ts` multistream, `orphans.ts` leftover-host cleanup. `src/main/preview-mac.ts` shows macOS preview surfaces in the window's process via the preview presenter (`native/preview_presenter.mm`).
- `src/main/chat/`: read-only live chat. `twitch-chat.ts` (anonymous IRC WebSocket, no token), `youtube-chat.ts` (polls the active broadcast's chat at YouTube's requested interval; each call costs API quota), `hub.ts` merges both and batches to the renderer, `twitch-eventsub.ts` (follows and channel-point redemptions; needs follower/redemption scopes, older sign-ins must reconnect). Chat connects only while the chat panel is visible.
- `src/main/overlay/`: overlay system. `presets/` (20 built-in designs, helpers in `presets/fields.ts`), `library.ts` (user overlays as JSON in app data), `runtime.ts` (the `window.SEENALYZE` API every overlay uses; keep in sync with the dashboard designer prompt `STUDIO_OVERLAY_RUNTIME_API` in `dashboard_app/src/lib/server/studio-overlay-contract.ts`), `document.ts` (CSP + settings CSS + runtime injection), `design.ts` (AI design validation), `data.ts` (chat/events/stats feed, runs only while an overlay is on screen), `server.ts` (local overlay server, 127.0.0.1 only, default port 47821, falls back to nearby ports and retargets saved overlay sources) serving the self-contained on-stream chat overlay page (`chat-page.ts`, text inserted as text nodes only) and its event stream. The "Chat overlay" source is a browser source pointing at it.
- `src/main/seenalyze/account.ts`: SEENALYZE sign-in (PKCE via the dashboard, `seenalyze-studio://` app link) and the AI overlay designer call (`/api/studio/overlays/generate`; credits are charged server-side, the dashboard owns model, key, and allowlist).
- `src/main/permissions.ts`: camera/microphone/screen-recording access. Capture sources must request access before the engine creates them, or capture silently yields black frames or silence. macOS judges access by the *responsible* app (the launcher of the process tree), so `bun run dev` starts Electron through `bin/dev-launcher` (`native/dev_launcher.c`, dev-only, not shipped), which disclaims responsibility so dev `Electron.app` asks for itself. Started directly from a terminal/editor, a hardened parent without the camera entitlement makes macOS refuse the camera without a prompt (`permission-camera-no-prompt`) and the app never appears in System Settings.
- `src/main/screen-recording/`: recording and editor, separate from the streaming engine. `index.ts` (`ScreenRecorder`, used by `studio.ts`), `capture.ts` (area/window/screen picker, one panel per display), `recording.ts` (native recorder on macOS, built-in browser recorder elsewhere), `interactions.ts` (pointer, clicks, typing timing; never which keys), `facecam.ts` (live camera bubble, own track), `controls.ts` (floating pause/stop bar, kept out of the video), `editor.ts` (editor windows, per-recording edits, export), `media-protocol.ts` (`recording-media:` scheme serving only registered files, with byte ranges), `speech.ts` + `windows-speech.ts` (local caption recognition: WhisperKit built from source on macOS, checksum-verified whisper.cpp on Windows; started on demand, stopped when idle), `recording-data.ts` (per-recording data in app data, never next to the video). Pages are plain browser modules in `src/renderer/screen-recording/<page>/`, text from `en.json` → `screenRecording` via `shared/i18n.js` (use-intl core); preloads are `src/preload/recording-<page>.ts`.
- `native/`: macOS helpers built into `bin/` (gitignored) by `scripts/build-native.mjs`: Swift executables (`screen-recorder`, `video-muxer`, `media-tools`, `window-list`, `audio-inputs`) and the preview presenter `preview_presenter.mm` (Node-API addon `bin/preview-presenter.node`, built with clang against the running Node's Node-API headers). The presenter shows each engine display in a Metal layer above the window content and copies only finished frames; Core Animation scales, so screen/scale changes need no rebuild. PowerShell scripts in `native/` are used as-is on Windows. Every file loaded from `bin/` must be in the mac `extraResources` filter in `electron-builder.yml`.
- `src/preload/`: exposes exactly the `StudioApi` contract on `window.studio`. `src/shared/`: IPC contract (`ipc.ts`), domain types, encoder planner, platform specs; no Electron/Node/libobs imports.
- `src/renderer/`: Vite + React 19 + Tailwind 4 + shadcn-style components. Design tokens mirror the SEENALYZE web dashboard. In-app icons are SVG only (lucide-react glyphs with `currentColor`, inline SVG platform marks in `components/PlatformIcon.tsx`, SVG app logo in `assets/icons`); never add PNG/raster UI icons.
- `vendor/` (gitignored): prebuilt libobs binding (`obs-studio-node`), fetched by `scripts/fetch-native-deps.mjs` from `native-deps.json` with pinned SHA-256 hashes; folders for dependencies no longer listed are removed.

## Commands
```bash
bun install                 # also fetches + verifies the engine (postinstall)
bun run dev                 # scripts/dev.mjs: native helpers + electron-vite dev (macOS: Electron via bin/dev-launcher)
bun run typecheck
bun run lint
bun test src                # planner + translation coverage tests
bun run check:multistream      # shared-encoder multistream check against local RTMP receivers (see script header)
bun run check:responsiveness   # hidden-window check: main thread never blocks, quit is fast, no leftover engine
bun run check:presets          # renders all overlay presets with demo data; fails on script errors
bun run check:screen-recording # hidden-window editor check on a generated video: load, save, export (needs ffmpeg)
bun run build:native           # macOS helpers + preview presenter into bin/ (dev and build run it; skips up-to-date ones)
bun run dist:mac | dist:win
```

## Rules specific to this project
- **One running instance.** Before building or launching, stop previous dev instances, `obs64 seenalyze-studio-*` engine hosts, and local test receivers.
- Engine calls are synchronous and can block for seconds (permission prompts, font/device enumeration, teardown), so they run only in the engine worker; main talks to it asynchronously with timeouts. Main may use only the preview presenter (via `preview-mac.ts`) and types from `engine/`; it must never call `loadOsn()` or any libobs object. Only `src/main/engine/*` touches libobs objects.
- Teardown (verified): never `release()` scenes/sources before engine shutdown; remove a scene's items before releasing the scene; order is `InitShutdownSequence` → `OBS_API_destroyOBS_API` → `IPC.disconnect` → stop the host process. Renamed sources keep their old name in the engine client, so always map names through `SceneGraph.nameOf`.
- Use the engine's short encoder names (`apple_h264`, `nvenc`, `amd`, `qsv`, `x264`); unknown names silently fall back to x264. Shared encoders: never enable per-output dynamic bitrate; a destination needing different video settings gets its own encoder group (`shared/planner.ts`).
- The preview is a native surface above the web UI. Every overlay root in `components/ui/overlays.tsx` hides it while open; new floating UI must use those primitives. On macOS the engine sizes preview surfaces in physical pixels, capped at canvas width (every frame is copied to the CPU).
- Engine crash reports stay on the user's machine. The engine's crash handler re-enables uploads on start and on every crash, and an empty crash server means its vendor's service, so `engine.ts` passes a closed loopback server (`LOCAL_CRASH_SERVER`) and switches uploads off after init. Never pass an empty `crashServerUrl`.
- Stream keys and OAuth tokens only through `src/main/secrets.ts` (Electron safeStorage); never log, persist in JSON, or send to the renderer. OAuth client IDs come from `config/studio.config.json` (gitignored; see the example). Never read `.env` files (blind-op exception per parent §10 only).
- All UI text goes through `use-intl` with keys in `src/renderer/messages/en.json`; main-process errors are kebab-case codes mapped under `errors.codes.*`. `messages.test.ts` enforces coverage.
- Overlays are untrusted (AI-generated) code. They run only inside the overlay CSP (no external scripts or network except images), and the editor previews them in a sandboxed frame. Insert user content as text (`SEENALYZE.renderSegments` / `textContent`); only `SEENALYZE.platformLogo()` output may use `innerHTML`.
- To add a Windows engine build, pin its SHA-256 in `native-deps.json` after verifying the archive.
- Screen recording: only the picker, camera bubble, and built-in recorder pages may use camera/microphone/screen in the renderer (`ScreenRecorder.allowsMedia`); the studio UI never does. Editor pages read files only through `recording-media:` URLs from `media-protocol.ts`. Every editor/recorder IPC handler checks the sender is its own window. Exports go to a temp file and are renamed into place; a failed export never replaces a file.

## Verification
Run `bun run typecheck`, `bun run lint`, `bun test src` after changes. Engine/output changes: also `bun run check:multistream` and `bun run check:responsiveness`. Screen-recording changes: `bun run check:screen-recording`; live capture, camera, system audio, and caption model setup need a manual pass (device access or large downloads). Don't drive the user's screen to verify; use the headless checks. Windows behaviour is not yet verified on hardware; say so when reporting.
